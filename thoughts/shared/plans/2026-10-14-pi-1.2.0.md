## Owner decisions (open; each blocks only the items named)

- **D1 -- What's New after an update (blocks P12-B2, P12-B3).** pi shows, on the first interactive start after an
  update (no messages in the session, `lastChangelogVersion` in settings.json older than the running version), a
  block between two rules: bold accent `What's New`, then every newer CHANGELOG section rendered as Markdown
  (interactive-mode.ts:850-871, 949, 1332-1356; utils/changelog.ts:100-190). A fresh install (no
  `lastChangelogVersion`) records the version silently; `collapseChangelog: true` shows one line instead
  (`Updated to vX. Use /changelog to view full changelog.`); `/changelog` shows every entry (interactive-mode.ts:
  6780-6802). This is NOT new in 1.2.0 (1.1.0 has it); amiga-pi has none of it (no `lastChangelogVersion`,
  `collapseChangelog` or `/changelog` anywhere in amiga-pi/). The question is which text amiga-pi shows:
  (a) amiga-pi's own CHANGELOG.md in pi's format (`## [1.2.0] - date`, keyed by PI_VERSION), shipped in the kit
  next to the binary; (b) pi's CHANGELOG verbatim; (c) not ported.
  **Recommended: (a)** because pi's text advertises features amiga-pi does not have (codemode, MCP sign-in,
  per-key OpenRouter lists unless D2), so (b) would tell Amiga users things that are false; the mechanism and the
  layout still match pi cell for cell (the golden feeds pi's own 1.2.0 section as a fixture file).
- **D2 -- Per-key OpenRouter model lists (blocks P12-A10).** pi 1.2.0 replaces the OpenRouter catalog, when an
  OpenRouter key is stored, with `GET <baseUrl>/models/user` (chat models the key may use, its context size, max
  output and prices; 401/403/404 keep the catalog; saved and used offline) (ai/src/providers/openrouter.ts:13-68,
  openrouter-api.ts:30-75; coding-agent core/model-runtime.ts:226-240, remote-catalog-provider.ts). amiga-pi has
  the same shape already for Radius (radius.c: refresh at interactive/RPC start, on /model, kept in
  models-store.json). Cost: one HTTPS GET whose body is the full model objects (size not measured; OpenRouter
  lists 300+ models) parsed on a 68k at start.
  **Recommended: port it (P12-A10), reusing radius.c's refresh/store path, after one size probe of the response
  with the owner's key** because it changes which models `/model` lists, so without it /model differs from pi for
  every OpenRouter user; the probe decides whether the Amiga needs a streaming filter instead of a whole-body parse.
